# リスク台帳 — dialogue-delta-formalization

> 用途: 企画 / 設計フェーズで挙がった懸念事項を一元管理。各リスクは出典 (どの議論で挙がったか) と対応方針 / オーナーを持つ。
> 関連: `.kiro/specs/dialogue-delta-formalization/personas-stories.md` (各 persona の「導入後の想定リスク」は persona 内に embed)

## 凡例

- **影響度**: H (止まる/再設計) / M (機能制限) / L (運用回避可)
- **確度**: H (現時点でほぼ確実に起きる) / M (条件次第) / L (理論上)
- **ステータス**: open / mitigating / accepted / closed

## R-01: 経験者 (供給側) が形式化に協力しないインセンティブ問題

| Field | 内容 |
|---|---|
| カテゴリ | 採用 / インセンティブ設計 |
| 影響度 | **H** — 供給側が回らないと corpus が育たず製品仮説が成立しない |
| 確度 | **M** — TMC 類似プロジェクトで実観測 |
| 出典 | 2026-05-20 meeting (TMC事例)。「自分の知見を共有することで自分の価値が下がる」懸念 |
| 詳細 | 経験豊富な供給側ユーザーが、暗黙知を形式化することで自身の希少性・市場価値が下がると感じ、協力を控える |
| 対応方針 | (1) 「共有による評価向上」を設計に組み込む (citation 数 / 引用された件数の可視化など) (2) 完全匿名化オプション (3) 共有しない選択を許容する UX |
| オーナー | @sotaro_suzuki (モチベーション設計 TODO に紐付け) |
| ステータス | open |

## R-02: 暗黙知の確からしさ / 重み付け設計

| Field | 内容 |
|---|---|
| カテゴリ | コア機能 / アルゴリズム |
| 影響度 | **H** — 重み付けが間違うと corpus 汚染 → 製品価値毀損 |
| 確度 | **H** — TMC プロジェクトでも未解決 |
| 出典 | 2026-05-20 meeting 「暗黙知の確からしさ/重み付けが最重要課題」 |
| 詳細 | 暗黙知 (個人の経験知) と形式化された情報 (社内規約等) の優先順位、複数 source 間の整合性、record ごとの信頼度スコアの算出方法が未定 |
| 対応方針 | (1) 暗黙知は「参考情報」として重み付けを低く設定 (default) (2) Truth Judgment フェーズで整合性チェック (3) 確からしさ検証は別フェーズで設計 (現スコープ外) |
| オーナー | TBD (design phase) |
| ステータス | open (Phase 2 で深掘り) |
