# 2026-05-11 ミーティング議事録

## 概要
Microsoft Agent Hackathon 2026 に向けた企画会議。暗黙知を形式知化するAIエージェントシステムの構想について議論し、方針を決定した。企業応募の手続き確認と、技術的実現可能性の検討を行った。

## 決定事項
- **メインテーマ**: 暗黙知の形式知化を主軸とした AIエージェントシステムの開発
- **応募形態**: 企業枠での応募を目指す(申込期限: 6月1日)
- **スコープ**: エンタープライズ向けに絞り、特定のドメイン/クライアントに限定して実装
- **システム概要**: 
  - ユーザーとAIの対話から差分を検知
  - 暗黒知と判断された情報を形式知化
  - 形式知として蓄積し、適切に引き出せるようにする
- **実装方針**: 完全実装より、アイデアの革新性と一部実装の完成度を重視

## 議論された論点

### 1. 企画の方向性
- 当初の3案(A: 案件立ち上げ/人材マッチング、B: 会議議事録管理、C: プロジェクト知見アーカイブ)から、暗黙知形式知化に集約
- @sotaro_suzuki提案の「ドメイン知識をつけるためのエージェント」をベースに議論
- 検索機能(RAG)と生成機能の両立を検討したが、暗黙知の形式知化に注力する方針

### 2. 暗黙知の定義と範囲
- **形式知化済み**: 既存の文書・資料として存在するもの
- **暗黙知**: 
  - 人の頭の中にのみ存在する知識
  - クライアント固有の人間関係、業務フロー、政治力学など
  - インターネットで調べても出てこない情報
- 形式知化の手法として、AIとの日常的な対話の中で差分を検知するアプローチを採用

### 3. 技術的実現可能性
- **懸念点**: 
  - データ生成フローの複雑さ
  - 試行回数の多さによる処理の重さ
  - プロンプト管理の難しさ
- **解決策**: 
  - スコープを特定ドメイン/クライアントに絞る
  - Azure のマネージドサービス活用
  - 欲しいデータ項目の事前定義によるガードレール設定

### 4. システムフロー(案)
1. 欲しいデータ(暗黙知の種類)を定義
2. ユーザーがAIと対話(日常業務の中で)
3. AIが既存の形式知と入力内容の差分を検知
4. 差分を暗黙知と判断し、形式知化のためのヒアリング開始
5. 形式知として蓄積(重み付け・ライフサイクル管理)
6. 次回以降の提案に活用

### 5. 個人開発 vs エンタープライズ
- エンタープライズ向けの方が課題の解像度が高い
- 個人開発では性格設定などがマークダウンで簡単に実装可能
- エンタープライズでは暗黙知の収集UIが必要
- 最終的にエンタープライズ向けに決定

### 6. データ管理・セキュリティ
- 個人情報や機密情報の取り扱い
- 入力・出力それぞれにガードレールが必要
- 古い情報の破棄基準
- データの重み付けによる信頼性管理

## オープン論点 / 次回への持ち越し
- 暗黙知の正誤判定方法(人間の入力を100%信頼しない仕組み)
- 公開情報との整合性チェックの必要性
- 具体的なドメイン/クライアントの選定
- エージェントへの「人間性」付与の要否と方法
- 詳細なアーキテクチャ設計
- テスト駆動 vs 通常開発のアプローチ
- AI部の社外展開(ワークショップのオープン化)の検討
