# 2026-05-20 ミーティング議事録

## 概要
AI部 Microsoft Agent Hackathon 2026 チームの企画会議。暗黙知の形式化をテーマとしたアプリケーション開発について、ペルソナ設定、ユースケース、業務フロー、技術要件などを議論。TMCでの類似プロジェクト経験を踏まえ、データの重み付けやインセンティブ設計の難しさについても共有された。

## 決定事項
- ペルソナをA(暗黙知を形式化したい人)、B・C(暗黙知を借りる/活用する人)の3タイプで整理する
- 業務フローは現段階では絞らず、汎用的なアプリケーションとして設計を進める(仕様段階で絞り込みを検討)
- 暗黙知の定義:「自分の中で言語化できていないもの」「形式化されていない状態」として統一
- C1〜C3のペルソナバリエーションは「どれかを選択する」形式とし、C4は矛盾検知を担う人間として位置付ける
- 暗黙知の確からしさ検証は、お水指し(OMUSUBI)等の手法とは別フェーズで考える

## 議論された論点

### ペルソナとユーザーフロー
- A(管理者/形式化したい人)、B(経験者/教える側)、C(ジュニア/学ぶ側)の3者構造
- Bは「自分の知見を共有することで自分の価値が下がる」懸念を持つ可能性(TMC事例)
- C1〜C3はスキルレベルのグラデーションとして設計、C4は矛盾検知の人間レビュアー

### 暗黙知の扱い
- 暗黙知の確からしさ/重み付けが最重要課題(TMCプロジェクトでも議論になった)
- 形式化された情報(社内規約等)と暗黙知の優先順位設計:暗黙知は「参考情報」として重み付けを低く設定
- 暗黙知の価値を定量化する見せ方が必要

### 業務フローと要件
- 現状は「暗黙知の収集→検索」の一貫フローを想定
- As-Is / To-Be / Result(恩恵)の構造で整理
- 矛盾検知は入力時と活用時の2パターンあり、設計要検討

### 技術面
- Discord音声チャンネルでのトランスクリプト議事録化の実験中
- ローカルモデル(オープンソース)での実装を検討中
- Claude等の高精度モデル利用も視野(IP許可前提)

## オープン論点 / 次回への持ち越し
- 業務フローを絞り込むタイミング(現段階では保留、仕様段階で検討)
- 暗黙知の確からしさ検証手法の具体化
- B・C側のインセンティブ設計(無意識的利用 vs 意識的協力)
- データ重み付けのアルゴリズム詳細
- Claude等高精度モデルの利用可否(セキュリティ・コスト面)
